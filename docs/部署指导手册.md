## 第一章 常用命令速查

本章介绍部署中用到的所有 Linux 命令。已经熟悉的可以跳过，用时再回来查。

### 1.1 远程连接类

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `ssh` | 登录远程服务器，相当于"进入另一台电脑的终端" | `ssh root@<服务器IP>` |
| `scp` | 在本机和服务器之间**传文件**（必须在本机执行，不是在服务器上） | `scp app.jar root@<服务器IP>:/opt/questrush/` |

- `scp` 的格式是 `scp <本机文件> <用户>@<地址>:<目标路径>`，方向反写就是把服务器文件拉回本机。
- 传大目录时先压缩：`tar czf` 打包 → 传包 → 服务器解包（见 1.3）。

### 1.2 身份与权限类

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `whoami` | 查看当前是哪个用户 | `whoami` → `root` |
| `su -` | 切换用户（**密码在回车后单独输入，屏幕不显示**） | `su -` 切到 root |
| `sudo` | 以 root 权限执行单条命令 | `sudo yum install xxx` |
| `chown` | 修改文件/目录的**归属** | `chown -R admin:admin /opt/questrush` |

三个最容易踩的坑：

1. **密码不能拼在 `su` 后面**。`su -密码` 会被当成参数报错。正确做法：`su -` 回车，等提示后再输密码。
2. **提示符就是身份标识**：`[admin@...]$` 是普通用户，`[root@...]#` 是管理员。装软件、写系统目录前先看一眼提示符。
3. `chown -R` 的 `-R` 表示递归整个目录，服务用普通用户跑、目录归属普通用户是标准做法。

### 1.3 文件操作类

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `ls` | 列出目录内容 | `ls -lh /opt/questrush/`（`-l` 详细信息，`-h` 人类可读大小） |
| `cd` | 切换目录 | `cd /opt/questrush` |
| `cp` | 复制文件/目录 | `cp nginx.conf nginx.conf.bak`（`-r` 复制目录） |
| `mv` | 移动/重命名 | `mv a.jar app.jar` |
| `rm` | 删除文件（**不可恢复，删前先 `ls` 确认路径**） | `rm app.log` |
| `mkdir` | 创建目录，`-p` 可一次建多级 | `mkdir -p /opt/questrush` |
| `cat` | 输出文件内容；配合 `>` 可整文件写入 | 见下方 |
| `tar` | 打包/解包 | `tar czf 包.tar.gz dist` 打包；`tar xzf 包.tar.gz -C 目标目录` 解压 |
| `tail` | 持续查看文件末尾（看日志神器） | `tail -f app.log`（Ctrl+C 退出） |

`cat` 的高级用法——**整文件写入**（部署中大量使用）：

```bash
cat > /etc/nginx/conf.d/questrush.conf << 'EOF'
这里是文件的完整内容
可以有很多行
EOF
```

`<< 'EOF'` 叫 heredoc：把两个 EOF 之间的内容整体写入 `>` 后面的文件。比 `vi` 手动编辑更不容易出错。

`tar` 参数记忆：
- `c`reate 打包 / e`x`tract 解包
- `z` 处理 .gz 压缩 / `f` 指定文件名
- `--strip-components=1`：解压时剥掉包里第一层目录（包里是 `dist/index.html`，剥掉 `dist/` 让文件直接落在目标目录）

### 1.4 进程与服务类

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `ps` | 查看进程 | `ps aux | grep java`（配合 grep 搜进程名） |
| `kill` | 结束进程，参数是 PID（ps 输出第二列） | `kill 335647`（`kill -9` 强杀，少用） |
| `ss` | 查看端口监听情况 | `ss -tlnp | grep 8080` |
| `nohup ... &` | 后台常驻运行，断开 SSH 不退出 | `nohup java -jar app.jar > app.log 2>&1 &` |
| `curl` | 发 HTTP 请求，验证服务是否存活 | `curl -I http://127.0.0.1` |

`nohup` 拆解：`> app.log` 把标准输出写进日志；`2>&1` 把错误输出也并进去；结尾 `&` 表示丢到后台。一条命令 = "在后台跑，日志写进 app.log，我关终端它也活着"。

`systemctl` —— 管理**系统服务**（相当于给进程配了一个"托管中心"）：

```bash
systemctl start nginx      # 启动
systemctl stop nginx       # 停止
systemctl status nginx     # 看状态
systemctl enable nginx     # 开机自启
systemctl enable --now nginx   # 自启 + 立即启动，一条顶四条
systemctl disable nginx    # 取消自启
```

前端类比：`nohup ... &` 是手动挂后台（类似终端里 `npm run dev &`），`systemctl` 是正规的进程托管（类似 pm2），**服务器重启后 systemctl 管的服务会自动回来，nohup 的不会**。

### 1.5 软件安装类（yum）

```bash
yum install -y java-17-openjdk java-17-openjdk-devel
```

`-y` 表示安装过程中的确认全部自动答 yes。装完多个版本并用 `alternatives --config java` 切换默认版本（输入编号回车）。

### 1.6 排查三件套

| 想知道什么 | 命令 |
| --- | --- |
| 服务起没起来 | `ss -tlnp | grep <端口>` |
| 服务为什么没起来 | `tail -100 <日志文件>` |
| 进程在不在 | `ps aux | grep <进程名>` |

### 1.7 MySQL 客户端的两层世界

```text
[root@... ~]# mysql -uroot -p     ← 终端层：执行 shell 命令
mysql>                            ← 数据库层：只能写 SQL，每条以 ; 结尾
```

- 看到 `mysql>` 提示符就**只能写 SQL**，把 `mysql -e "..."` 这种终端命令粘进去必报 1064。
- SQL 没写完时提示符会变成 `->` 或 `">`（引号没闭合），按 `Ctrl+C` 放弃当前语句重来。
- `exit` 退出回终端层。

## 第二章 部署架构

```text
浏览器
   │  http://<服务器IP>
   ▼
Nginx :80
   ├── /            → /var/www/questrush     （前端静态文件，Vite build 产物）
   └── /api/*       → http://127.0.0.1:8080  （Spring Boot 后端）
                                        │
                                        ▼
                                  MySQL 8 :3306（仅本机访问）
                                        └── quest_rush 库
```

对应本地联调的关系：Nginx 的 `/api` 反代 = Vite 的 `server.proxy`；`npm run dev` 的 5173 端口在 production 不存在，静态文件直接由 Nginx 托管。

**目录约定**：

| 路径 | 内容 | 归属 |
| --- | --- | --- |
| `/opt/questrush/app.jar` | 后端 jar | admin |
| `/opt/questrush/app.log` | 后端日志 | admin |
| `/opt/questrush/uploads/` | 头像等上传文件（自动创建） | admin |
| `/var/www/questrush/` | 前端静态文件 | nginx 可读 |
| `/etc/nginx/conf.d/questrush.conf` | 站点配置 | root |

## 第三章 部署步骤

> 约定：`[本机]` = 在自己 Mac 的终端执行；`[服务器]` = ssh 登录服务器后执行。
> 所有 `<尖括号>` 内容替换为真实值（记录在 LOCAL_SETUP.md）。

### 阶段 1：本地打包 `[本机]`

```bash
# 后端（产物：backend/target/quest-rush-backend-1.0.0.jar）
cd <项目路径>/backend
mvn package -DskipTests

# 前端（产物：frontend/dist/）
cd ../frontend
npm run build
```

### 阶段 2：服务器安装 JDK 17 `[服务器]`

服务器默认是 Java 8，项目要求 17：

```bash
su -                                          # 切 root（密码回车后输入）
yum install -y java-17-openjdk java-17-openjdk-devel
alternatives --config java                    # 多版本时输入 17 的编号
java -version                                 # 必须显示 17.x
```

### 阶段 3：建库 + 专用账号 `[服务器]`

```bash
mysql -uroot -p<MySQL-root密码>
```

进入 `mysql>` 后执行（`<DB密码>` 自己定强密码并记入 LOCAL_SETUP.md）：

```sql
CREATE DATABASE IF NOT EXISTS quest_rush DEFAULT CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'quest_rush'@'localhost' IDENTIFIED BY '<DB密码>';
GRANT ALL ON quest_rush.* TO 'quest_rush'@'localhost';
FLUSH PRIVILEGES;
exit
```

> ⚠️ SQL 里的占位符要整体替换，连引号一起，别把占位符文字本身当密码。
> 后端只给它 localhost 权限和单独的库，不用 root 连业务。

### 阶段 4：上传产物 `[本机]`

```bash
cd <项目路径>
ssh root@<服务器IP> "mkdir -p /opt/questrush /var/www/questrush"

scp backend/target/quest-rush-backend-1.0.0.jar root@<服务器IP>:/opt/questrush/app.jar
scp backend/sql/init.sql root@<服务器IP>:/tmp/init.sql

cd frontend && tar czf /tmp/dist.tar.gz dist
scp /tmp/dist.tar.gz root@<服务器IP>:/tmp/
```

回到服务器收尾 `[服务器]`：

```bash
mysql -uroot -p<MySQL-root密码> < /tmp/init.sql     # 报"表已存在"无害
tar xzf /tmp/dist.tar.gz -C /var/www/questrush --strip-components=1

# 三样验证
ls -lh /opt/questrush/                              # app.jar（约 50MB）
ls /var/www/questrush/                              # index.html + assets/
mysql -uroot -p<MySQL-root密码> -e "USE quest_rush; SHOW TABLES;"
```

> ⚠️ 若解压报 `Permission denied`：用 root 执行 tar；若目录要给 admin 用，先 `chown -R admin:admin <目录>`。

### 阶段 5：启动后端 `[服务器]`

用普通用户跑（不要用 root）：

```bash
# 若目录归属不是 admin，先切 root 执行：
#   chown -R admin:admin /opt/questrush
su - admin
cd /opt/questrush
DB_USERNAME=quest_rush DB_PASSWORD='<DB密码>' \
  nohup java -jar app.jar > app.log 2>&1 &

tail -f app.log        # 看到 Started LearnApplication 即成功；Ctrl+C 退出
ss -tlnp | grep 8080   # 看到 java 监听即成功
```

说明：`DB_USERNAME`/`DB_PASSWORD` 走环境变量注入，密码不落盘、不进命令行历史之外的任何文件。首次启动自动写入 admin 账号与种子题目（幂等，表非空不重复插入）。

### 阶段 6：配置 Nginx `[服务器，root]`

```bash
# 站点配置
cat > /etc/nginx/conf.d/questrush.conf << 'EOF'
server {
    listen 80;
    server_name _;
    root /var/www/questrush;
    index index.html;

    # /api 转给后端，路径保持不变（等价于 vite 代理）
    location /api {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # history 路由刷新不 404
    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF

# 备份并重写主配置（移除旧 server 块，避免抢 80 端口）
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
cat > /etc/nginx/nginx.conf << 'EOF'
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    access_log /var/log/nginx/access.log;
    sendfile on;
    keepalive_timeout 65;

    include /etc/nginx/conf.d/*.conf;
}
EOF

# 检查并启动
nginx -t                     # 必须 syntax is ok / test is successful
systemctl enable --now nginx
curl -I http://127.0.0.1     # HTTP/1.1 200 OK
```

### 阶段 7：云防火墙/安全组 `[控制台]`

- 入方向放行 **TCP 80**（轻量应用服务器在"防火墙"页，ECS 在"安全组"页）
- **删除 3306 的公网入规则**（MySQL 只应本机访问，公网开放属于高危配置）

### 阶段 8：验证 `[本机浏览器]`

1. 打开 `http://<服务器IP>` → 出现前端页面
2. 用管理员账号登录 → 能刷题即全链路通
3. 邮箱验证码为 mock 实现，验证码打印在后端 `app.log` 中

## 第四章 常见问题（排障速查）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `su -密码` 报 event not found | 密码拼进了命令 | `su -` 回车后单独输密码 |
| `yum install` 报权限错误 | 当前不是 root | `su -` 后重试，看提示符确认 |
| SQL 报 1064 | 终端命令粘进了 `mysql>` | 先看提示符；`mysql>` 里只写 SQL |
| `mysql>` 卡在 `">` | 引号没闭合 | `Ctrl+C` 放弃当前语句 |
| tar 报 Permission denied | 普通用户写系统目录 | `su -` 用 root 执行，或先 chown |
| 后端 `app.log: Permission denied` | 运行目录归 root | `chown -R admin:admin /opt/questrush` |
| `tail -f app.log` 报 Access denied | DB 密码不对 | 核对阶段 3 的 `<DB密码>` |
| 页面 502 | 后端没起来 | `tail -100 /opt/questrush/app.log` |
| 页面能开但接口全挂 | Nginx 没配 /api 转发 | 检查 questrush.conf，`nginx -t` 后重启 |
| curl 通但浏览器打不开 | 云防火墙没放行 80 | 控制台添加 TCP 80 入规则 |
| 刷新页面 404 | 缺 history 回退 | 确认 `try_files $uri $uri/ /index.html;` |
| 注册收不到邮箱验证码 | MailService 为 mock | 验证码在 `app.log` 里 |

## 第五章 日常运维

### 更新后端

```bash
# [本机] 重新打包并上传
mvn package -DskipTests
scp backend/target/quest-rush-backend-1.0.0.jar root@<服务器IP>:/opt/questrush/app.jar

# [服务器] 重启进程（找到旧 PID 再 kill，再按阶段 5 启动）
ps aux | grep java
kill <旧PID>
```

### 更新前端

```bash
# [本机]
npm run build && tar czf /tmp/dist.tar.gz dist && scp /tmp/dist.tar.gz root@<服务器IP>:/tmp/
# [服务器]
tar xzf /tmp/dist.tar.gz -C /var/www/questrush --strip-components=1
```

前端更新无需重启任何进程。

### 看日志 / 看状态

```bash
tail -100 /opt/questrush/app.log     # 后端最近 100 行日志
systemctl status nginx               # nginx 状态
ss -tlnp                             # 当前所有监听端口
```

### 完整下线（如需）

```bash
# [服务器]
ps aux | grep java        # 找 PID
kill <PID>                # 停后端
rm /opt/questrush/app.jar # 删 jar（删前确认不再需要）
systemctl stop nginx && systemctl disable nginx
```

MySQL 与数据库数据建议保留（删库不可逆）。
