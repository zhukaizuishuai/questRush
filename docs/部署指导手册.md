## 第一章 常用命令速查

本章介绍部署中用到的所有 Linux 命令。已经熟悉的可以跳过，用时再回来查。
每个命令都标了**英文全称**——记住全称，命令本身就不用背了。

### 1.1 远程连接类

| 命令 | 英文全称（中文直译） | 作用 | 示例 |
| --- | --- | --- | --- |
| `ssh` | **S**ecure **Sh**ell（安全外壳协议） | 登录远程服务器，相当于"进入另一台电脑的终端" | `ssh root@<服务器IP>` |
| `scp` | **S**ecure **C**opy（安全复制） | 在本机和服务器之间**传文件**（走 ssh 加密通道，必须在本机执行，不是在服务器上） | `scp app.jar root@<服务器IP>:/opt/questrush/` |

- `scp` 的格式是 `scp <本机文件> <用户>@<地址>:<目标路径>`，方向反写就是把服务器文件拉回本机。
- 传大目录时先压缩：`tar czf` 打包 → 传包 → 服务器解包（见 1.3）。
- 同类命令：`sftp` = **S**ecure **F**ile **T**ransfer **P**rotocol（安全文件传输），可交互式反复上传下载；`rsync` = **r**e**m**ote **sync**（远程同步），只传改动的部分，大目录更好用。

### 1.2 身份与权限类

| 命令 | 英文全称（中文直译） | 作用 | 示例 |
| --- | --- | --- | --- |
| `whoami` | 不是缩写，就是英文短语 **who am I**（我是谁） | 查看当前是哪个用户 | `whoami` → `root` |
| `su` | **S**witch **U**ser（切换用户，也解作 Substitute User 替代用户） | 切换用户（**密码在回车后单独输入，屏幕不显示**） | `su -` 切到 root |
| `sudo` | **S**uper**U**ser **DO**（"以超级用户的身份去做"） | 以 root 权限执行单条命令 | `sudo yum install xxx` |
| `chown` | **CH**ange **OWN**er（更改所有者） | 修改文件/目录的**归属** | `chown -R admin:admin /opt/questrush` |
| `chmod` | **CH**ange **MOD**e（更改模式位） | 改读/写/执行权限（本项目少用，但排障常碰到） | `chmod +x start.sh` |

三个最容易踩的坑：

1. **密码不能拼在 `su` 后面**。`su -密码` 会被当成参数报错。正确做法：`su -` 回车，等提示后再输密码。
2. **提示符就是身份标识**：`[admin@...]$` 是普通用户，`[root@...]#` 是管理员。装软件、写系统目录前先看一眼提示符。
3. `chown -R` 的 `-R` = **R**ecursive（递归），表示连目录里的子文件一起改；服务用普通用户跑、目录归属普通用户是标准做法。

### 1.3 文件操作类

| 命令 | 英文全称（中文直译） | 作用 | 示例 |
| --- | --- | --- | --- |
| `ls` | **LiSt**（列出） | 列出目录内容 | `ls -lh /opt/questrush/`（`-l` = **l**ong format 详细信息，`-h` = **h**uman-readable 人类可读大小） |
| `cd` | **C**hange **D**irectory（切换目录） | 切换目录 | `cd /opt/questrush` |
| `cp` | **C**o**P**y（复制） | 复制文件/目录 | `cp nginx.conf nginx.conf.bak`（`-r` = **r**ecursive 递归，复制目录用） |
| `mv` | **M**o**V**e（移动） | 移动/重命名 | `mv a.jar app.jar` |
| `rm` | **R**e**M**ove（移除） | 删除文件（**不可恢复，删前先 `ls` 确认路径**） | `rm app.log` |
| `mkdir` | **M**ake **DIR**ectory（创建目录） | 创建目录，`-p` = **p**arent，父目录不存在时一并创建 | `mkdir -p /opt/questrush` |
| `cat` | **CAT**enate（串联：把文件内容首尾相接吐到屏幕） | 输出文件内容；配合 `>` 可整文件写入 | 见下方 |
| `tar` | **T**ape **AR**chive（磁带归档——早期备份写磁带，如今只是包格式） | 打包/解包 | `tar czf 包.tar.gz dist` 打包；`tar xzf 包.tar.gz -C 目标目录` 解压 |
| `tail` | 不是缩写，就是英文"尾巴"（与 `head`「头部」相对） | 持续查看文件末尾（看日志神器） | `tail -f app.log`（`-f` = **f**ollow 跟随，Ctrl+C 退出） |

`cat` 的高级用法——**整文件写入**（部署中大量使用）：

```bash
cat > /etc/nginx/conf.d/questrush.conf << 'EOF'
这里是文件的完整内容
可以有很多行
EOF
```

`<< 'EOF'` 叫 heredoc = **Here Document**（"文档就写在这里"）；`EOF` = **E**nd **O**f **F**ile（文件结束标记，告诉 shell"到这里为止都是我写的内容"）。把两个 EOF 之间的内容整体写入 `>` 后面的文件，比 `vi`（**Vis**ual **i**nterface，可视化编辑器）手动编辑更不容易出错。

`tar` 参数记忆：
- `c`reate 打包 / e`x`tract 解包
- `z` 处理 .gz 压缩（`.gz` = **G**NU **z**ip）/ `f` = **f**ile 指定文件名 / `-C` = **C**hange 先切到目标目录再解压
- `--strip-components=1`：解压时剥掉包里第一层目录（包里是 `dist/index.html`，剥掉 `dist/` 让文件直接落在目标目录）

### 1.4 进程与服务类

| 命令 | 英文全称（中文直译） | 作用 | 示例 |
| --- | --- | --- | --- |
| `ps` | **P**rocess **S**tat**u**s（进程状态） | 查看进程 | `ps aux \| grep java`（`a` = **a**ll users 所有用户的进程，`u` = 按 **u**ser 显示归属，`x` = 含没有终端的进程） |
| `kill` | 不是缩写，就是英文"杀死"——本质是给进程**发信号**，默认 SIGTERM（**TER**minate 终止） | 结束进程，参数是 PID（ps 输出第二列） | `kill 335647`（`kill -9` = SIGKILL 强杀，不给进程清理机会，少用） |
| `ss` | **S**ocket **S**tatistics（套接字统计；它替代的老命令 `netstat` = **NET** **STAT**istics） | 查看端口监听情况 | `ss -tlnp \| grep 8080`（`t`=**t**cp、`l`=**l**istening 只看在监听的、`n`=**n**umeric 不做名字反解、`p`=**p**rocess 显示进程） |
| `nohup ... &` | **NO** **H**ang-**UP**（不挂断） | 后台常驻运行，断开 SSH 不退出 | `nohup java -jar app.jar > app.log 2>&1 &` |
| `curl` | **C**lient for **URL**s（URL 客户端，官方读作 "see-URL"） | 发 HTTP 请求，验证服务是否存活 | `curl -I http://127.0.0.1`（`-I` 只要响应头，HEAD 请求） |
| `PID` | **P**rocess **ID**entifier（进程标识号） | 进程的唯一编号，`kill` 的参数就是它 | `ps aux` 输出第二列 |

`nohup` 拆解：`> app.log` 把标准输出（stdout = **st**andar**d** **out**put）写进日志；`2>&1` 把标准错误（stderr = **st**andar**d** **err**or，文件编号 2）也并进标准输出（编号 1）；结尾 `&` 表示丢到后台。一条命令 = "在后台跑，日志写进 app.log，我关终端它也活着"。

`systemctl` —— **SYSTEM** **C**ONTro**L**（系统控制），管理**系统服务**（相当于给进程配了一个"托管中心"）。它管的 `systemd` = **System D**aemon，末尾 `d` 是 Unix 惯例，表示 daemon（守护进程，一直在后台值守的程序）：

```bash
systemctl start nginx      # 启动
systemctl stop nginx       # 停止
systemctl status nginx     # 看状态
systemctl enable nginx     # 开机自启
systemctl enable --now nginx   # 自启 + 立即启动，一条顶四条
systemctl disable nginx    # 取消自启
```

前端类比：`nohup ... &` 是手动挂后台（类似终端里 `npm run dev &`），`systemctl` 是正规的进程托管（类似 pm2），**服务器重启后 systemctl 管的服务会自动回来，nohup 的不会**。

### 1.5 软件安装类（yum）

```bash
yum install -y java-17-openjdk java-17-openjdk-devel
```

`-y` = **y**es，表示安装过程中的确认全部自动答 yes。`java-17-openjdk` 里的 **OpenJDK** = **Open** **J**ava **D**evelopment **K**it（开放版 Java 开发套件），`-devel` = **devel**oper（开发包，含编译需要的头文件）。装完多个版本并用 `alternatives --config java` 切换默认版本（输入编号回车，`alternatives` 是英文原词"备选方案"，非缩写）。

> `yum` 全称 **Y**ellowdog **U**pdater, **M**odified——Yellowdog 是早期一个 Linux 发行版（Yellow Dog Linux）的名字，Modified 表示它的改进版。较新的系统上它已被 `dnf`（**D**andified **Y**um，"升级化版的 yum"）取代，命令写法基本一致。

### 1.6 排查三件套

| 想知道什么 | 命令 |
| --- | --- |
| 服务起没起来 | `ss -tlnp \| grep <端口>` |
| 服务为什么没起来 | `tail -100 <日志文件>` |
| 进程在不在 | `ps aux \| grep <进程名>` |

两个贯穿全书的记号：
- `grep` = **G**lobal **R**egular **E**xpression **P**rint（全局按正则表达式搜索并打印），来自老编辑器 `ed` 的一条命令 `global /regular expression/ print`。
- `|` 读作 **pipe**（管道），把前一个命令的输出"接"给后一个命令当输入，所以 `ps aux | grep java` = 先列出全部进程，再从里面挑含 java 的行。

### 1.7 MySQL 客户端的两层世界

```text
[root@... ~]# mysql -uroot -p     ← 终端层：执行 shell 命令
mysql>                            ← 数据库层：只能写 SQL，每条以 ; 结尾
```

- 看到 `mysql>` 提示符就**只能写 SQL**，把 `mysql -e "..."` 这种终端命令粘进去必报 1064。
- SQL 没写完时提示符会变成 `->` 或 `">`（引号没闭合），按 `Ctrl+C` 放弃当前语句重来。
- `exit` 退出回终端层（英文原词"退出"，非缩写）。

命令与名称的全称：
- `mysql` / `MySQL`：产品名，本身不是缩写；其中的 **SQL** = **S**tructured **Q**uery **L**anguage（结构化查询语言）。
- `mysqld` 末尾的 `d` = **d**aemon（守护进程，即真正跑在后台的那个 MySQL 服务）。
- `mysql -uroot -p`：`-u` = **u**ser（用哪个账号），后面紧跟账号名；`-p` = **p**assword（提示输密码），后面紧跟密码；两者连写 `-uroot -p密码`。
- `mysqldump` = mysql + **dump**（"倒出来"，即导出成 SQL 文本）。

## 第二章 部署架构

```text
浏览器
   │  http://<服务器IP>
   ▼
Nginx :80
   ├── /            → /var/www/questrush     （前端静态文件，Vite build 产物）
   └── /api/*       → http://127.0.0.1:8080  （Spring Boot 后端）
                                        │
                                        ▼
                                  MySQL 8 :3306（仅本机访问）
                                        └── quest_rush 库
```

对应本地联调的关系：Nginx 的 `/api` 反代 = Vite 的 `server.proxy`；`npm run dev` 的 5173 端口在 production 不存在，静态文件直接由 Nginx 托管。

**目录约定**：

| 路径 | 内容 | 归属 |
| --- | --- | --- |
| `/opt/questrush/app.jar` | 后端 jar | admin |
| `/opt/questrush/app.log` | 后端日志 | admin |
| `/opt/questrush/uploads/` | 头像等上传文件（自动创建） | admin |
| `/var/www/questrush/` | 前端静态文件 | nginx 可读 |
| `/etc/nginx/conf.d/questrush.conf` | 站点配置 | root |

## 第三章 部署步骤

> 约定：`[本机]` = 在自己 Mac 的终端执行；`[服务器]` = ssh 登录服务器后执行。
> 所有 `<尖括号>` 内容替换为真实值（记录在 LOCAL_SETUP.md）。

### 阶段 1：本地打包 `[本机]`

```bash
# 后端（产物：backend/target/quest-rush-backend-1.0.0.jar）
cd <项目路径>/backend
mvn package -DskipTests

# 前端（产物：frontend/dist/）
cd ../frontend
npm run build
```

### 阶段 2：服务器安装 JDK 17 `[服务器]`

服务器默认是 Java 8，项目要求 17：

```bash
su -                                          # 切 root（密码回车后输入）
yum install -y java-17-openjdk java-17-openjdk-devel
alternatives --config java                    # 多版本时输入 17 的编号
java -version                                 # 必须显示 17.x
```

### 阶段 3：建库 + 专用账号 `[服务器]`

```bash
mysql -uroot -p<MySQL-root密码>
```

进入 `mysql>` 后执行（`<DB密码>` 自己定强密码并记入 LOCAL_SETUP.md）：

```sql
CREATE DATABASE IF NOT EXISTS quest_rush DEFAULT CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'quest_rush'@'localhost' IDENTIFIED BY '<DB密码>';
GRANT ALL ON quest_rush.* TO 'quest_rush'@'localhost';
FLUSH PRIVILEGES;
exit
```

> ⚠️ SQL 里的占位符要整体替换，连引号一起，别把占位符文字本身当密码。
> 后端只给它 localhost 权限和单独的库，不用 root 连业务。
> SQL 关键词直译：`CREATE DATABASE` 建库；`CREATE USER ... IDENTIFIED BY` 建用户并用……认证；`GRANT ALL ON ... TO` 把……上的全部权限授予；`FLUSH PRIVILEGES` 刷新权限表让授权立即生效。

### 阶段 4：上传产物 `[本机]`

```bash
cd <项目路径>
ssh root@<服务器IP> "mkdir -p /opt/questrush /var/www/questrush"

scp backend/target/quest-rush-backend-1.0.0.jar root@<服务器IP>:/opt/questrush/app.jar
scp backend/sql/init.sql root@<服务器IP>:/tmp/init.sql

cd frontend && tar czf /tmp/dist.tar.gz dist
scp /tmp/dist.tar.gz root@<服务器IP>:/tmp/
```

回到服务器收尾 `[服务器]`：

```bash
mysql -uroot -p<MySQL-root密码> < /tmp/init.sql     # 报"表已存在"无害
tar xzf /tmp/dist.tar.gz -C /var/www/questrush --strip-components=1

# 三样验证
ls -lh /opt/questrush/                              # app.jar（约 50MB）
ls /var/www/questrush/                              # index.html + assets/
mysql -uroot -p<MySQL-root密码> -e "USE quest_rush; SHOW TABLES;"
```

> ⚠️ 若解压报 `Permission denied`：用 root 执行 tar；若目录要给 admin 用，先 `chown -R admin:admin <目录>`。

### 阶段 5：启动后端 `[服务器]`

用普通用户跑（不要用 root）：

```bash
# 若目录归属不是 admin，先切 root 执行：
#   chown -R admin:admin /opt/questrush
su - admin
cd /opt/questrush
DB_USERNAME=quest_rush DB_PASSWORD='<DB密码>' \
  nohup java -jar app.jar > app.log 2>&1 &

tail -f app.log        # 看到 Started LearnApplication 即成功；Ctrl+C 退出
ss -tlnp | grep 8080   # 看到 java 监听即成功
```

说明：`DB_USERNAME`/`DB_PASSWORD` 走环境变量注入，密码不落盘、不进命令行历史之外的任何文件。首次启动自动写入 admin 账号与种子题目（幂等，表非空不重复插入）。

### 阶段 6：配置 Nginx `[服务器，root]`

```bash
# 站点配置
cat > /etc/nginx/conf.d/questrush.conf << 'EOF'
server {
    listen 80;
    server_name _;
    root /var/www/questrush;
    index index.html;

    # /api 转给后端，路径保持不变（等价于 vite 代理）
    location /api {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # history 路由刷新不 404
    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF

# 备份并重写主配置（移除旧 server 块，避免抢 80 端口）
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
cat > /etc/nginx/nginx.conf << 'EOF'
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    access_log /var/log/nginx/access.log;
    sendfile on;
    keepalive_timeout 65;

    include /etc/nginx/conf.d/*.conf;
}
EOF

# 检查并启动
nginx -t                     # 必须 syntax is ok / test is successful
systemctl enable --now nginx
curl -I http://127.0.0.1     # HTTP/1.1 200 OK
```

## 第四章 常见问题（排障速查）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `su -密码` 报 event not found | 密码拼进了命令 | `su -` 回车后单独输密码 |
| `yum install` 报权限错误 | 当前不是 root | `su -` 后重试，看提示符确认 |
| SQL 报 1064 | 终端命令粘进了 `mysql>` | 先看提示符；`mysql>` 里只写 SQL |
| `mysql>` 卡在 `">` | 引号没闭合 | `Ctrl+C` 放弃当前语句 |
| tar 报 Permission denied | 普通用户写系统目录 | `su -` 用 root 执行，或先 chown |
| 后端 `app.log: Permission denied` | 运行目录归 root | `chown -R admin:admin /opt/questrush` |
| `tail -f app.log` 报 Access denied | DB 密码不对 | 核对阶段 3 的 `<DB密码>` |
| 页面 502 | 后端没起来 | `tail -100 /opt/questrush/app.log` |
| 页面能开但接口全挂 | Nginx 没配 /api 转发 | 检查 questrush.conf，`nginx -t` 后重启 |
| curl 通但浏览器打不开 | 云防火墙没放行 80 | 控制台添加 TCP 80 入规则 |
| 刷新页面 404 | 缺 history 回退 | 确认 `try_files $uri $uri/ /index.html;` |
| 注册收不到邮箱验证码 | MailService 为 mock | 验证码在 `app.log` 里 |

### 更新后端

```bash
# [本机] 重新打包并上传

scp backend/target/quest-rush-backend-1.0.0.jar root@<服务器IP>:/opt/questrush/app.jar
```

```bash
# [本机]
npm run build && tar czf /tmp/dist.tar.gz dist && scp /tmp/dist.tar.gz root@<服务器IP>:/tmp/

tar xzf /tmp/dist.tar.gz -C /var/www/questrush --strip-components=1
```
